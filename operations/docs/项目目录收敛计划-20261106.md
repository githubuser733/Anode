**Goal:** 工作目录只保留当前 Anode 发布包、一个重建并检查过的上一版回滚包；源码、开发工具、本机数据和快捷入口分别归类。

**Architecture:** 当前运行程序和现用监控库保持原位。合并两个 Git 工作区的有效源码到独立开发目录，保留所有分支与当前改动。迁移未运行的工具和用户数据，校验每个文件，更新日常入口所读取的路径。旧测试产物按审核清单回收，不用把所有历史再复制一遍的方式代替清理。

**Tech Stack:** Windows PowerShell、Python 3.12、Git、已有 .NET 10 SDK、本项目现有完整性检查。

**Spec:** 当前用户要求，以及本轮指定的三个对话：`01a18de6-3474-7012-8541-e9414e1d8ac4`、`01a1a7b7-37ce-7543-a3f0-ce231317613c`、`01a1a0f9-6dff-7380-8fb8-8fea54d37470`。

## Global Constraints

- 所有产物保留在 `F:\AI infrastructure\agent-Windows-operation` 内。
- 不重启 Anode、不退出 Windows 子会话、不移动运行中的应用目录。
- 监控进度、数据库、提醒与转发回执、用户配置和凭据均保留。
- 目标路径不得覆盖已有文件；改配置前保留可恢复原件。
- 新回收清单必须重新展示绝对路径、文件数与大小，并取得用户本次主动回复 `1989`；只用 Windows 回收站。

## Review Focus

- 关联工作区依赖原 Git 数据库：新目录须核对全部分支、标签、源码与未提交改动，不能只复制工作文件。
- 上一个 v6 包已不在记录的回收站路径：只能明确标注为根据保留源码重建的回滚候选，不能冒称原二进制或实际登录已验证。
- 三个对话的改动跨越源码、系统帧率设置和 UU 脚本：分别保留；不重新应用注册表或远控开关。
- 运行目录与用户数据含绝对路径及目录链接：迁移只处理未运行目录，保留链接本身，核对归属记录和启动参数。
- 历史测试证据与当前业务状态混放：活跃数据库和日志排除回收；对待回收目录逐项扫描备份、密钥和凭据名称，独有恢复材料归类保留。
