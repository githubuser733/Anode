WorkBuddy 为什么要专用入口

主桌面和 Anode 子会话共用文件系统，但 WorkBuddy 的默认 Electron 运行目录
有单实例锁。第二次普通启动可能通知主桌面实例后退出，子会话看起来没有反应。
专用启动脚本对新进程设置：
WORKBUDDY_CONFIG_DIR=C:\Users\Zhang\.workbuddy
CODEBUDDY_CONFIG_DIR=C:\Users\Zhang\.workbuddy
WORKBUDDY_USER_DATA_DIR=F:\AI infrastructure\agent-Windows-operation\work\recheck-20261031-shared\workbuddy-electron
前两项让聊天和业务配置共用主桌面目录，后一项让两个会话分别持有运行锁。
这些环境变量只影响本次启动的进程，不写入系统全局环境。
启动器会检查当前是否为 Anode 子会话，从主桌面直接启动会拒绝并说明原因。

目录使用约定

主配置 C:\Users\Zhang\.workbuddy 是 WorkBuddy 的实际业务目录，应继续共用。
项目 work 内的独立 Electron 运行目录也继续沿用；运行中不复制或迁移它。
Anode 自身状态和系统日志仍在 C:\Users\Zhang\AppData\Local\Anode。
这些应用标准目录不属于 Codex 对话交付目录。
所有本项目脚本、快捷方式、参数记录、测试报告与截图均以本项目为入口。
历史归档保持原始字节和旧路径文字，仅作证据；当前操作以 README 和 config 为准。

MCP 工具桥

在项目根目录的 PowerShell 中执行：
$bridge = .\scripts\Start-ProjectMcp.ps1
& .\scripts\internal\live_call.ps1 -Port $bridge.port -Tool seat_status

Start-ProjectMcp 会复用本项目已运行的桥，或隐藏启动新的本地 Python 桥。
工具端口由系统动态分配，不要写死旧端口。
它只初始化 MCP 客户端；不会启动、停止或重建 Windows 子会话。
新证据写入 artifacts\mcp\project-mcp-<时间>-<随机标记>\anode。
运行元数据在 work\project-mcp-<时间>-<随机标记>\anode\bridge.json。
seat_status 只读，不会争抢键鼠。其他工具仍需遵循 Anode 的 lease 与人工控制规则；
完整工具说明在 config 指向的 anodeGuide 文件。

scripts\Test-ProjectSetup.ps1：检查配置、脚本语法、快捷方式和逐文件哈希。

不打开应用；主桌面正常应显示 allowed=false。
Initialize 不覆盖已存在且内容不同的快捷方式；更改配置前先保留原文件。
