# Agent 操作：Anode 优先与数据一致性

以后代劳本机／远机桌面应用时，默认优先使用 Anode；先观察原始主桌面，再决定如何接手应用。

1. **先看远机窗口。** 确认远控连接的是原始主桌面还是 Anode 子会话，观察目标程序是否已打开；必要时核对托盘、后台进程及所属会话。不能把“没看到窗口”当成“应用未运行”，也不能用子会话状态代替主桌面检查。
2. **优先处理尚未打开过的应用。** 远机尚未打开过的应用优先交给 Anode。以前用过、当前已关闭的应用，仍须先找到原有业务数据目录，避免启动后读写另一份数据。
3. **已打开的应用先处理原实例或共享入口。** 优先保存工作、正常退出远机原实例，确认退出后，再从 Anode 读取同一份数据；或在 Anode 中创建／复用指向远机原有业务数据目录的快捷方式。不得丢弃未保存内容或直接强杀进程。
4. **共享入口必须真正共用数据。** 核对快捷方式目标、启动参数、工作目录和业务数据的实际绝对路径；参数与目录映射须按应用当前版本验证。允许按需隔离运行目录，但两边业务数据必须指向同一实际位置；复制配置、复用登录或显示相同账号，都不能单独证明数据一致。
5. **共享目录不等于可同时写入。** 只有该应用的主桌面与 Anode 组合已验证支持并发读写，才可保留两端同时操作；否则先关闭一端，再使用另一端。无法确认原实例状态、真实数据目录或共享方式时，先暂停该应用的数据写入并说明缺口。
6. **操作后核验。** 核对原有内容可读，并在本次任务授权范围内验证保存后另一端能读到相同结果；未验证并发时按顺序切换验证。仅建好快捷方式不算通过，未做实机验证的部分标记 UNTESTED。可复用入口放 launchers/，已验证参数放 config/，验证证据放 artifacts/；应用升级或目录变化后重新核验。

执行顺序：观察远机 → 确认实例与数据目录 → 退出原实例或验证共享入口 → 在 Anode 操作 → 核验两端数据一致。

# Agent 操作补充：备用渠道顺序

本节补充前文的 Anode 默认流程；桌面操作渠道按 Anode → 本地 Ghost 项目 → Computer use 的顺序选择。

1. **先检查 Anode。** 通过 seat_status 等只读方式确认状态；Anode 已启动且可用时优先使用。插件列表中没有 Anode 不代表它未启动，可通过本项目 MCP 桥查询；查询失败也不能直接当作未启动。
2. **Anode 未启动时临时使用 Ghost。** 转用用户指定的本地 Ghost 项目；默认先走这个备用渠道，不为维持 Anode 优先级而自行启动或重建 Anode 子会话。用户明确要求启动 Anode 时按该次任务执行。
3. **最后才考虑 Computer use。** Ghost 不可用或无法完成当前任务时，再考虑使用 Computer use，并简要说明切换原因。
4. **沿用应用与数据核验要求。** 无论采用哪个渠道，都先确认实际操作的桌面／会话、应用是否已打开及业务数据目录；切换渠道后重新观察并核验结果，避免重复启动或读写另一份数据。
5. **Ghost 入口须先核实。** 截至 2026-11-04，本次尚未核实该本地项目的路径、启动参数和工具接口。首次调用前查找项目并读取其说明，验证实际入口；不得猜测命令或将其他同名 Ghost 工具当作用户指定的项目。
