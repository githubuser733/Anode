# Anode 后续维护评估

核查日期：2026-10-31。对象包括上游 `skulitom/Anode` 和本项目的 Timeline 改版。

结论：上游短期继续维护的迹象较好，但长期保障较弱；我们的改版可以继续维护，成本中等，需要保留源码、构建环境和实机回归。没有足够历史数据给出可信的百分比或“多久后一定出 bug”。

| 问题 | 判断 | 依据和边界 |
|---|---|---|
| 未来 1–3 个月继续有维护 | 中高，主观判断 | 最近仍有提交、缺陷修复与 CI；不代表已经承诺后续发布 |
| 未来一年以上稳定维护 | 不确定，宜保守 | 仓库仅约 7 周历史，主要代码贡献集中在一个人，未形成可见的接替团队 |
| 继续使用当前固定版本 | 可行，但不是免维护 | 本机核心流程已验证；Windows、应用和 RDP 变化仍可能造成问题 |
| 维护我们的 Timeline 改版 | 中等成本 | 本地改动范围有限且有回归，但部分改动进入上游也频繁修改的核心文件 |

本地改版的维护成本

本次实际核对本地清单：相对 v0.11.3 共 11 个源码/文档文件新增或修改；源码哈希与 publish-004 的候选清单一致。项目根目录和源码目录均没有 `.git`，目前依靠原始源码压缩包、补丁和哈希清单保存差异。仅“有源码”还不等于已具备方便升级的 Git 分支。

上游在我们的基线 `0836c780c75eb68afcd15b825c9d62d61fd32b0b` 之后已有 29 个提交、82 个文件变化。双方都改到 `Cli.cs`、`SelfTest.cs`、`AnodeDaemon.cs` 三个文件；这是合并审查点，不是已经证实有三个文本冲突。[基线到主分支差异](https://github.com/skulitom/Anode/compare/0836c780c75eb68afcd15b825c9d62d61fd32b0b...main)

较敏感的两处实现：

- `work/anode-timeline-20261031/source/src/Anode/Daemon/PointerGuard.cs:10` 描述了对 `mstscax.dll` 的 `SetCursorPos` 导入进行进程内保护；第 24 行起使用固定模块/导入名称。这是对 Windows 组件行为的依赖，Windows 更新后需要复测，不能承诺永久兼容。
- `work/anode-timeline-20261031/source/src/Anode/Daemon/ViewerThreadMessages.cs:32` 枚举 Viewer 子窗口线程，第 51 行安装限定线程的消息观察。真人记录依赖 RDP 的实际消息路径，所以 38 项离线检查不能代替每次升级后的真人验证。

这两点是基于已读源码作出的风险判断，不是已经观察到将来的故障。

建议的维护方式

1. 固定当前可用的 publish-004，不直接用上游安装包覆盖 Timeline 版。
2. 保留源码、原始源码包、补丁、私有 .NET SDK、NuGet 依赖和最后一次真实验收证据；可移走旧 build/publish 输出。
3. 下次升级时在有 Git 历史的维护分支中合并上游，先检查三个重叠文件，再执行离线检查、Agent 输入、人工接管/归还、隐藏运行、剪贴板及焦点验证。
4. 不再扩展 BgDesk 分支；Anode Timeline 已不依赖 BgDesk 的可执行程序或源码目录。保留最小历史说明即可，不需要为 Timeline 运行保留多个 BgDesk 构建。

尚未解决的风险

- 本机 `osd` 自启动窗口曾抢占子会话焦点；Timeline 的 ok 仅表示工具返回成功，不保证应用收到输入。
- 完整上游 `selftest --quick` 尚未在本地运行。`SelfTest.cs:44` 有文件删除逻辑，与本项目删除规则冲突；未删改或弱化测试。
- 自动化的 Timeline 折叠实机检查未完成；长期运行及各种应用兼容性未验证。
- 不能预测准确故障时间。应重点关注 Windows 更新、Anode 合并升级和桌面应用升级这些变化节点。
