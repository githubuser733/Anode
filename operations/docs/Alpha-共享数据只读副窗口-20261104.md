# Alpha 共享数据只读副窗口

已实测：主桌面运行原 Alpha，Anode Session 7 运行只读副窗口，两端共用原 Alpha 后台。未改造原版程序或单实例锁，副窗口不直接读写业务数据库。副窗口支持账号选择、会话分页、消息分页、关键词搜索和手动刷新。

**当前范围**：这是独立的只读查看界面。图片、音视频播放、朋友圈和原版完整界面尚未接入；搜索结果点击后打开该会话的最新消息，暂不定位到命中消息。两个原版 Alpha 同时写入没有实现，也未验证。应用锁定后的实际解锁恢复未在本轮操作（UNTESTED）；原程序正常退出、重新启动后的断开和恢复已实测。

## 日常使用

1. 在主桌面打开原 Alpha，保持解锁。在「设置 → 接口与集成」确认本机 HTTP API 运行中，地址为 `http://127.0.0.1:5031`。
2. Anode 已启动、登录且处于查看模式时，在主桌面双击 [Alpha-ReadOnly-In-Anode.lnk](../launchers/Alpha-ReadOnly-In-Anode.lnk)。它自动将只读副窗口打开到现有 Anode 子桌面，不会启动或重建子会话；有其他 Agent 占用时会拒绝接管。
3. 在 Anode 副窗口选择会话，或点「搜索消息」。顶部「刷新」从原后台重新读取；没有自动实时推送。
4. 发送、编辑等操作继续使用主桌面的原 Alpha。关闭副窗口不影响原 Alpha；原 Alpha 退出或锁定时，副窗口不能继续读取，重新打开／解锁后点刷新。

旧 [Alpha-Shared-In-Anode.lnk](../launchers/Alpha-Shared-In-Anode.lnk) 仍保留，供关闭主实例后顺序切换原版使用。日常同时显示两端时使用新的 ReadOnly 入口。

## 按官方文档实施

先读取用户指定仓库的两个接口文档，固定提交 `09232cbca892241fd3d2046957832a6b4d764ddc`：

- [HTTP API](https://github.com/xunchahaha/alpha-releases/blob/09232cbca892241fd3d2046957832a6b4d764ddc/docs/api/http-api.md)：原 Alpha 须保持打开；Bearer 鉴权；浏览器 Origin 限制；接口分页和错误不能当作空数据。
- [MCP](https://github.com/xunchahaha/alpha-releases/blob/09232cbca892241fd3d2046957832a6b4d764ddc/docs/api/mcp.md)：同一个令牌也能访问发送工具，不能将它交给浏览器并仅隐藏发送按钮。

实现只允许四类 GET 读取：账号、会话、消息和搜索。不开放通用 MCP 转发，不开放发送、导出、媒体下载等路径，不接受 POST/PUT/PATCH/DELETE 等请求；Host、Origin、浏览器跨站请求、重复参数、额外参数及分页大小均在代理端检查。原令牌仅在代理内存中使用，不放到页面、浏览器存储或 URL。

本机搜索参数存在版本细节：`query + limit` 实测返回 400；依据运行时工具 schema 改为显式 `account_id + query + page_size` 后返回 200，分页使用 `next_cursor`。可复核 [documentation-audit.json](../artifacts/alpha-readonly-20261104-143007-cc7122/documentation-audit.json) 与 [live-readback.json](../artifacts/alpha-readonly-20261104-143007-cc7122/live-readback.json)。

启用接口时首次生成的令牌曾在工具截图中可见，因此在正常退出 Alpha 后已更换为新随机令牌，并保持加密保存；旧令牌实测返回 401。新令牌没有输出到工具日志或页面。旧加密配置备份保留于本次证据目录，未经授权没有删除。
