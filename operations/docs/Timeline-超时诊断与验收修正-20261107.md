## 证据与原因

- 对迁移时构建的原二进制复测：前两轮通过，第三轮再次在快速切换三张截图后超时。原错误是 `Activity fixture did not receive the expected UI update within five seconds`，当时位置为 `ActivityResponsivenessChecks.cs:88`。
- 原完整检查在 CLI 的 STA 线程上创建控件，通过 `Application.DoEvents()` 临时处理消息，没有持续的主消息循环。临时循环退出后，WinForms 会恢复之前的同步上下文。正式 Viewer 则使用 `Application.Run()`，见 `src/Anode/Daemon/AnodeDaemon.cs:170`。
- 诊断失败记录显示：界面操作在线程 2；开始解码时上下文已从 `WindowsFormsSynchronizationContext` 变为普通 `SynchronizationContext`；图片解码后续操作到了线程 7。三张文件存在且解码成功，但后台更新和前台切换竞争，最终仍选中 Agent、预览为空、加载标志和待处理请求均已清空。
- 原有 `LoadPreviewAsync` 依赖正常 WinForms 上下文返回界面线程（`src/Anode/Daemon/TimelinePanel.cs:378`）。本次没有修改它，也没有把这段测试竞争直接认定为正式 Viewer 中已复现的故障。
- 对照框架版本为 .NET WinForms 10.0.13。官方代码在消息循环计数归零时卸载同步上下文，见 [Application.ThreadContext.cs:811](https://github.com/dotnet/winforms/blob/v10.0.13/src/System.Windows.Forms/System/Windows/Forms/Application.ThreadContext.cs#L811-L815)。结论同时有本机执行轨迹支撑。
