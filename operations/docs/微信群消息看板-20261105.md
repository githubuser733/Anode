# 群消息监测看板

打开 **http://127.0.0.1:5033/**，或双击本项目 `launchers\群消息监测看板.lnk`。看板已接入真实监控记录，并在浏览器中保留为交付页面。

项目位置：`F:\AI infrastructure\agent-Windows-operation`。

## 页面能看什么

- **监控总览**：当前启停／连接状态、检查时间、累计读取消息数、命中数、已显示提醒及等待合并数；同时展示两个群的进度与命中趋势。
- **命中记录**：按群聊、时间范围、关键词、提醒状态筛选，支持搜索发言人／正文、分页和原文详情。关键词在列表中高亮。
- **提醒记录**：展示本机通知回执与对应 Markdown 摘录。“系统已显示”指操作系统返回显示回执，不能称为用户已读。
- **导出**：按当前筛选生成 Markdown；原提醒的完整摘录也可以单独下载。

统计卡片为首次启用后的累计值；列表与趋势按所选范围筛选。时间范围基于**发现时间**，详情里的消息时间可能更早，特别是在断线补读时。仅展示当前两群白名单内的记录。

网页约每 2 秒刷新，切到后台后放慢到约 5 秒。核心采集继续采用用户选定的 2 秒间隔、首次命中立即提醒、后续密集命中合并；网页只读取已记录的结果。

## 数据连续性

看板没有另开监控，也不重新调用 Alpha 接口。原读取器继续把消息、命中、检查点、通知和回执写入 `artifacts\wechat-resident\state\monitor.sqlite3`；看板使用只读连接，关闭网页不会停止记录。新增看板时没有停止 Anode、微信、Alpha 或原托盘进程。

记录在读取器第一次启用后开始累积，不代表完整微信历史。原来的 5 分钟回看、每窗 2000 条覆盖限制仍适用。提醒页展示最近最多 100 条通知；累计数字不受这个显示上限影响，历史命中可在“命中记录”中分页检索。一次 Markdown 导出最多 5000 条，末尾注明实际导出数与总数。

## 启动和停止

网页服务由独立的 Windows 计划任务 `AgentWindowsOperation-WeChatDashboard` 运行，入口为已有的 `pythonw.exe`，不会创建控制台窗口。保留每分钟检查与登录后触发；重复启动会复用已运行服务。

在项目 PowerShell 中使用：

```powershell
.\scripts\Control-WeChatDashboard.ps1 -Action Status
.\scripts\Control-WeChatDashboard.ps1 -Action Start
.\scripts\Control-WeChatDashboard.ps1 -Action Stop
```

正常状态应显示 `enabled=true`、`running=true`、`url=http://127.0.0.1:5033/`。Stop 只停止网页服务，关键词监控继续；核心监控仍由原托盘菜单和 `Control-WeChatResident.ps1` 管理。

只监听 `127.0.0.1`，手机或其他电脑不能直接访问这个地址。当前按本机配套实现，没有上传到云端 Site、绑定网页账号或暴露外网端口。

## 用户复核清单

1. 打开本机地址或看板快捷方式，应出现“正在监控”、两个指定群和真实统计，稍等可看到检查时间继续变化。
2. 切换“命中记录”，选 UA，应只保留符合 UA 边界的记录；点击消息正文可查看原文。
3. 切换“提醒记录”，下载一份 Markdown 摘录；也可点击页面右上角“导出记录”导出当前筛选结果。
4. 在项目目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Control-WeChatDashboard.ps1 -Action Status`，正常结果为 `enabled/running=true`。
5. 回归检查：`python -X utf8 -B -m unittest discover -s scripts/wechat_dashboard -p test_dashboard.py -v`，预期 `Ran 13 tests` 与 `OK`。
6. 项目检查：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test-ProjectSetup.ps1`，预期末行为 `PROJECT_SETUP_OK`。
